# ADR-0003: 判定はルールエンジン、LLM は文章化だけ

- 状態：採用
- 日付：2026-10-05

## 背景

レポートを LLM にすべて書かせると、映像にない数値や根拠のない指摘を書くおそれがある。セルフ分析では、指摘の根拠を確かめられることが信頼につながる。

## 決定

- 「何が・どれだけ・どのフレームで」ずれているかは、ルールエンジン（`judge/`）が判定する。
- LLM（Ollama のローカルモデル）には判定結果の JSON だけを渡し、読みやすい日本語の文章にさせる。
- LLM の出力に、渡していない数値が含まれていないかを検査する。含まれていたらテンプレート文に切り替える。

## 結果

- レポートの数値は必ず解析結果と一致する。
- LLM がなくてもテンプレート文でレポートを出せる。

## 実装（M3-3）

- 判定は `apps/web` のルール（`domain/judgement.ts`・`domain/coaching.ts`）が行い、テンプレートの文章（`TemplateFindingWriter`）をすぐに出す。
- 手元の Ollama が使えれば、改善点ごとに材料（指標・自分の値・お手本ゾーン・外れた側・自己ベスト・テンプレートの文章を下書きとして）を渡し、書き直してもらう（`OllamaNarrator`、既定のモデルは `gemma3:12b`）。
  - 出力は JSON（title・body）に限る（Ollama の structured outputs）。
  - 指示では、判定を変えない、渡した数値だけを使う、「大きいほど良い」と書かない、原因の推測や下書きにない体の動かし方を書かない（直し方は範囲に近づける意識と、登録したドリル動画の名前だけ）、2D の推定なので言い切りすぎない、を求める。
  - 試したとき、指示だけでは、判定にない体の動かし方（「腰を回旋させて前傾を大きく」）や、存在しないドリル動画の名前を書くことがあった。前者は指示で抑え、後者は次の検査で必ず止める。
- 出力の数値の検査（`application/narration.ts`）：
  - 文章の中の数値を取り出し（全角も半角にそろえる）、渡した値と、その桁で一致するかを確かめる。
  - ドリル動画を渡していないのに「ドリル」「動画」に触れていれば、存在しないドリル動画を挙げているとみなす。
  - 1 つでも合わなければテンプレートの文章に戻し、その理由を画面に出す。
- 書いた文章は、モデル・指示文の版・材料のハッシュをキーにしてブラウザに覚え、同じ判定なら書き直さない（M4 の Mac で 1 本 15〜25 秒）。
- Ollama がない（公開デモ、起動していない）ときは、テンプレートの文章のまま出す。公開デモには LLM の文章を入れていない。
