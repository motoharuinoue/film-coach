## ポートフォリオとして評価される仕掛け

- **サーバー不要のライブデモ**：解析済みの JSON とサンプル動画だけで、スタジオ・レポート・お手本ライブラリ（埋め込みと骨格）が動く「デモモード」を GitHub Pages に公開する。
- **精度評価**：数十フレームを手作業でアノテーションし、次の誤差を測って README に掲載する。
  - 骨格の PCK
  - リリースフレームの誤差（±フレーム）
  - 指標と手計測の誤差
- **重み付けの妥当性の検証**：人気度だけで重み付けした場合と、P×C×Q×K×M で重み付けした場合とで、お手本分布の安定性を比べる。安定性はブートストラップでの分散で測る。
- **README**：ヒーロー GIF、アーキテクチャ図、なぜ作ったか、実測した精度と速度、既知の限界。
- **品質**：pytest（合成骨格で指標計算、固定データで重み計算を検証）、Vitest、Playwright E2E、CI。依存の向き（クリーンアーキテクチャ）もテストで検査する。
- **ADR**：設計判断の理由を `docs/adr/` に残す。

## 検証方法

| | 検証 |
|---|---|
| M0 | `npm run dev` で全画面を確認。型検査とビルドが通る。Pages の URL で表示を確認 |
| M1 | `uv run pytest`（合成骨格で角度・時間の計算を検証）。ローカルファイルと YouTube URL の両方で解析し、同じ形式の結果が出ること、元動画が解析後に削除されることを確認。手計測と比べ、動画 10 秒あたりの処理時間を測る |
| M2 | 固定した情報（再生数・高評価数・指標値）から重みと分布が期待どおりに計算されることを pytest で確認。外れ値を混ぜたテストデータで、合意度 K が外れ値の重みを下げることを確認。API の利用量が無料枠に収まることをログで確認 |

## 要確認事項（M1 までに決める）

- 自分で撮った QB の動画（横から・後方から）を用意できるか。デモと精度評価の素材になる。
- ライセンスを MIT と Apache-2.0 のどちらにするか（リポジトリは公開済み）。
- YouTube の取得機能の扱い：[ADR-0005](adr/0005-youtube-terms-and-copyright.md) の方針で進めてよいか。初期設定を「Creative Commons のみ」にするか。
- 最初に登録する信頼チャンネルの候補（QB コーチ系のチャンネル）。
- アプリ名・ロゴの方向性。
