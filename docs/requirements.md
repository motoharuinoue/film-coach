# 要件定義

## 1. コンセプト

**「自分専用の AI フィルムルーム」**

自分の動画を、YouTube から集めたお手本の集合と自己ベストの両方と比べる。QB の投球動作を骨格レベルで分解し、「何がどれだけずれているか」を根拠のフレームと練習ドリルを添えて示す。

### 差別化のポイント

1. **2 つの基準を持つ**
   - 自分の基準：自己ベストとの差、レップ間のばらつき
   - お手本の基準：YouTube のお手本を重み付けして集計した分布
2. **重み付けの根拠を全部見せる**：お手本 1 本ごとに「なぜこの重みなのか」を内訳で表示する。人気だけに頼らない。
3. **全部ローカルで処理する**：外部と通信するのは YouTube の検索・情報取得・区間の取得だけ。
4. **ルールエンジンが判定し、LLM は文章にするだけ**：数値をでっち上げない（[ADR-0003](adr/0003-rules-judge-llm-writes.md)）。

## 2. 前提

| 項目 | 決定内容 |
|---|---|
| 利用者 | 選手本人（セルフ分析） |
| 動画 | 練習ドリルと試合映像の両方 |
| 最初に作り込むポジション | QB |
| 処理基盤 | ローカル Mac（Apple M4 / 32GB）+ Python。有料サーバーは使わない |
| 入力経路 | ローカルファイルのアップロードと YouTube URL の指定 |

## 3. ペルソナとユーザージャーニー

**ペルソナ**：高校〜大学・社会人の QB。コーチが付きっきりで見てくれる環境ではなく、自分で撮って自分で直したい。

**ジャーニー**

1. （初回）お手本ライブラリを作る
2. 撮影ガイドを見て撮る
3. ファイルか YouTube URL で取り込む
4. レップが自動で切り出される
5. スタジオで自分とお手本を比べる
6. レポートを読む
7. お手本のドリル動画で練習する
8. 次の撮影で推移を確認する

## 4. 機能要件

★ は見せ場になる機能。

### 4.1 取り込み

- **ローカルファイル**：mp4 / mov（iPhone の HEVC を含む）、30〜240fps、720p 以上。ドラッグ&ドロップで受け付ける。
- **YouTube URL**：
  1. URL を貼る
  2. タイトル・長さ・fps・解像度を表示する
  3. 開始・終了時刻を指定する
  4. 指定した区間だけを取得する（yt-dlp の `--download-sections`）
  - 想定用途：チームがアップロードした自分の試合映像など
- どちらの経路でも ffmpeg で H.264 と一定 fps に正規化し、以降は同じパイプラインに流す。取り込み元は `SourceAdapter` で抽象化する。
- **品質チェック**：fps・解像度・カメラ角度（横／後方／正面／エンドゾーン／サイドライン）を推定し、向かない指標があれば警告する。
- ★**レップの自動切り出し**：長い動画から、投球動作（手首速度のピーク）やスナップを検出して 1 本ずつに分ける。
- **撮影ガイド**：おすすめの画角・距離・fps を図で示す。

### 4.2 解析パイプライン

| 段階 | 手法 |
|---|---|
| 人物検出 | RTMDet（rtmlib 同梱、Apache-2.0） |
| 追跡 | ByteTrack（MIT） |
| ★対象選手のロック | SAM 2（Apache-2.0）。試合映像で 1 回タップすると、そのプレー中ずっと追う |
| 2D 骨格推定 | RTMPose / RTMW（rtmlib、ONNX Runtime + CoreML） |
| 平滑化・正規化 | One Euro / Savitzky-Golay。身長・肩幅で正規化した骨格座標も持つ |
| ★フェーズ分割 | ルールベースで 5 フェーズに分ける（下記） |
| ★フィールド座標変換 | ヤードライン・ハッシュを検出してホモグラフィ変換し、俯瞰図にする。4 点手動指定のフォールバックあり |
| ★3D 化（後半） | MotionBERT などで 2D→3D に持ち上げる |
| レポート文章 | Ollama のローカル LLM。JSON 出力にし、テンプレート文のフォールバックを持つ |

**フェーズの定義**

| フェーズ | 始まりの判定 |
|---|---|
| ドロップ | 動作の開始（スナップ、または体の移動の開始） |
| セット | 後ろ足が止まり、重心の移動が止まる |
| ステップ | 前足が地面から離れる |
| リリース | 前足の接地後、投げる側の手首速度がピーク |
| フォロースルー | リリース後、手首速度が下がり始める |

### 4.3 QB 指標

指標ごとに「有効なカメラ角度」と「信頼度」を持つ。カメラ角度が合わない指標は判定しない。

**ドリル**

| 指標 | 単位 | 有効なカメラ角度 |
|---|---|---|
| 始動からリリースまでの時間 | 秒 | すべて |
| ステップ幅 | 身長比 | 横 |
| ステップ方向（オープン／クローズ） | 度 | 後方・正面 |
| 接地時の前膝角度 | 度 | 横 |
| ★腰と肩の捻り差の最大値 | 度 | 後方・正面（3D 化後は横も） |
| ★キネマティックシーケンス | 順序・時間差 | 横・後方 |
| リリース時の肘の高さ | 肩比 | 横・後方 |
| リリース時の肘角度 | 度 | 横 |
| リリース点の高さ | 身長比 | 横 |
| アームスロット | 度 | 後方・正面 |
| 体幹の前傾 | 度 | 横 |
| 頭の安定性 | 身長比 | すべて |
| セット時のベース幅 | 肩幅比 | 後方・正面 |
| フォロースルー | 判定 | すべて |

キネマティックシーケンスは、骨盤 → 体幹 → 腕の順に回転速度がピークを迎えているかを見る。

**試合映像**

| 指標 | 単位 |
|---|---|
| スナップからリリースまでの時間 | 秒 |
| ドロップの深さ | yd |
| ポケット内の移動軌跡 | yd |
| リリース時の最寄りディフェンダーとの距離 | yd |

**一貫性**

- レップ間のリリース点・ステップ幅のばらつき（標準偏差）。
- ★全レップのリリース点を重ねた散布図で見せる。

### 4.4 判定

| 基準 | 内容 |
|---|---|
| 自分の基準 | 自己ベストとの差、レップ間のばらつき |
| お手本の基準 | お手本の重み付き分布の中での位置（重み付き中央値・四分位） |
| 初期値 | お手本が足りない指標は `metrics.yaml` の初期値を使う。初期値は「仮説」と明記する |

判定の状態は「良好／注意／要改善／判定不可」の 4 つ。判定不可には理由を添える。

### 4.5 ★お手本ライブラリ

YouTube のトレーニング動画などを、お手本（教師データ）として取り込む。

#### 集める

- YouTube Data API v3 で検索する（無料枠 1 日 10,000 ユニット）。
  - 検索語の例：「QB throwing mechanics」「quarterback footwork drill」
- 取得する情報：再生数・高評価数・チャンネル登録者数・公開日・ライセンス（Creative Commons かどうか）・チャプター。
- 信頼できるコーチのチャンネルを登録しておくと、新しい動画を自動で候補に入れる。

#### 取り込む

1. 埋め込みプレイヤーで内容を確認し、使う区間（開始・終了）を指定する。
2. 区間だけを取得し、通常と同じパイプラインで骨格・フェーズ・指標を出す。
3. 派生データ（骨格・指標）と出典だけを残し、元の動画は解析後に削除する（[ADR-0005](adr/0005-youtube-terms-and-copyright.md)）。
4. タイトルと説明文をローカル LLM で分類する（お手本の投球／ドリル解説／NG 例）。ポジション・ドリルの種類・カメラ角度のタグも付ける。

#### 重み付け

お手本ごと・指標ごとに計算し、内訳を UI に表示する（[ADR-0006](adr/0006-reference-weighting.md)）。

```
w(お手本, 指標) = 人気度 P × 発信者 C × 解析品質 Q(指標) × 合意度 K(指標) × 手動調整 M
```

| 要素 | 内容 |
|---|---|
| P（人気度） | 高評価率をベイズ平均で補正し、再生数は対数で効かせる。低評価数は 2021 年以降公開されていないので使わない |
| C（発信者） | 登録者数を対数で効かせる。登録した信頼チャンネルには加点する |
| Q（解析品質） | 関節検出の信頼度、カメラ角度がその指標に合っているか、解像度・fps |
| K（合意度） | 他のお手本の分布から大きく外れる値は、ロバスト z スコアで重みを下げる |
| M（手動調整） | ピン留め・除外・星評価 |

重み付き分布は、指標ごとの「お手本ゾーン」として、スタジオとレポートのグラフに帯で表示する。

#### 使い道

- ★**お手本とのゴースト比較**：体格を正規化した骨格を DTW でリリースに合わせて重ねる。重みの高いお手本か、自分に近い体格・アームスロットのお手本を自動で選ぶ。
- **お手本の基準での判定**（4.4）。
- **ドリルの推薦**：改善点に、そのドリルを解説している YouTube 動画（埋め込み・タイムスタンプ付き）を紐付ける。
- （発展）お手本のデータを教師ラベルとして、フェーズやイベントを検出する軽量モデルを学習させ、ルールベースと精度を比べる。

### 4.6 レポート・比較・推移

- ★**ゴースト比較**：自己ベストかお手本の骨格を半透明で重ねる。左右に並べた同期再生もできる。お手本の元動画は YouTube 埋め込みプレイヤー（IFrame API の `seekTo` で同期）で横に並べる。
- ★**AI コーチレポート**
  - 総合スコア
  - 7 軸のレーダーチャート（自分・自己ベスト・お手本ゾーンを重ねる）
  - 改善点トップ 3（注釈付きの根拠フレーム・説明・目標値・ドリル動画）
  - 良かった点
  - 一貫性
  - 参照したお手本の出典一覧
- **出力**：PDF（印刷用 CSS + Playwright）と静的 HTML。
- **推移ダッシュボード**：指標ごとの時系列、お手本ゾーンの帯、自己ベストの更新履歴。
- **テレストレーション**：一時停止中のフレームに線・角度・矢印を書き込める。

## 5. 非機能要件

| 分類 | 要件 |
|---|---|
| プライバシー | 自分の動画と解析はすべてローカルで処理する |
| 規約・著作権 | YouTube 由来の動画は個人の手元での解析に限り、解析後に削除する。表示は公式の埋め込みプレイヤーで行う（[ADR-0005](adr/0005-youtube-terms-and-copyright.md)） |
| 秘密情報 | YouTube Data API キーは `.env`（git 管理外）か macOS Keychain に保存する。リポジトリやログに出さない |
| 性能 | 10 秒・60fps のドリル動画を M4 で 1 分以内に解析する（M1 で実測） |
| 精度の透明性 | 単眼 2D の限界を UI 上で明示する。カメラ角度が合わない指標はグレーアウトし、理由を表示する |
| アクセシビリティ | 日本語 UI。状態は色だけでなくアイコンでも示す |
| 公開デモ | 再生する映像は自分で撮ったものだけ。写り込んだ他人の顔はぼかす |
